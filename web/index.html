Built to get out of your way

Every feature answers one question: does it delete manual work?

One command

lambo init detects your framework from evidence - artisan, composer.json, wp-config - and writes the environment to lambo.yml, showing every probe, including the ones that came back negative.

lambo init

No sudo, ever

Everything lives in %USERPROFILE%\Lambo or ~/.lambo. Ports are unprivileged (8080/8443), the installer is per-user, and the database binds to loopback only.

lambo config set server.port 8080

Native, not Docker

Real filesystem, real localhost, real debugger. Your OS is the runtime - Lambo manages it, so there is no compose file and no volume mount to debug.

lambo status

Environment as code

lambo.yml is human-readable YAML you commit. PHP version, server, database, extensions - the whole environment travels with the repository, with relative paths only.

php: "8.4" # pins the 8.4.x line

Doctor, with an answer

Home, transport, catalogue, runtimes, ports, project, services - lambo doctor checks them in the order lambo up uses, and every finding names the command that fixes it.

lambo doctor

Workspaces

Group the projects you actually work on. A workspace is a list of directories and nothing more, so a project behaves the same inside and outside one.

lambo workspace add

The road ahead

The engine is done. What is left is release engineering, and it is listed honestly.

  1. ✓

    Engine and CLI shipped

    PHP, Apache and MariaDB installed and supervised; init, up, down, status, open, doctor, logs, db, server, config, migrate. 318 tests, clippy clean on Windows, Linux and macOS.

  2. 1

    Pinned checksums next

    The catalogue ships with sha256: null, so a fresh machine cannot install anything until you pin a digest. That is the one thing standing between here and "just works".

  3. 2

    Apache and MariaDB for macOS planned

    No catalogue entries yet; Homebrew's builds are found on PATH in the meantime, or use server.kind: php.

  4. 3

    HTTPS planned

    server.https_port is reserved and the configuration models it, but no local CA is generated yet - lambo up serves plain HTTP on 8080 and says so.

  5. 4

    Workspaces that start planned

    Per-project ports already work. What is missing is starting a whole workspace and tracking which project holds which port.

Install in one line

One binary, no sudo, nothing else to install. Windows users: LamboPHP-Setup.exe from Releases.

curl -fsSL https://raw.githubusercontent.com/flessan/kink-php-dev/main/scripts/install.sh | sh

Everything it installs

One binary, plus %USERPROFILE%\Lambo or ~/.lambo on first use. That is the whole footprint.

From source

git clone https://github.com/flessan/kink-php-dev && cd kink-php-dev && cargo build --release

Uninstall

Run the uninstaller, or rm -rf ~/.lambo ~/.local/bin/lambo. Your data is never deleted for you.

Windows users: grab LamboPHP-Setup.exe or the portable LamboPHP-windows-amd64.zip from Releases. Portable mode: set LAMBO_HOME anywhere - even a USB stick.
