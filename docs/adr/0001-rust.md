# ADR-0001: Implementation language - Rust

- **Status:** Accepted
- **Date:** 2026-07-30

## Context

Lambo PHP manages processes, filesystems, certificates, and long-lived
developer machines. It must start in milliseconds, never corrupt state,
ship as one binary per OS, and be maintainable by a large open-source
community.

Candidates: Rust, Go, C++, Zig, and "PHP itself".

## Decision

**Rust**, stable channel, MSRV 1.85 (verified in CI).

## Rationale

- **Fast startup, tiny binaries.** No runtime, no interpreter warm-up; our
  performance budget (`lambo --help` < 50 ms) is trivially reachable.
- **Memory safety without a GC.** A tool that edits system trust stores and
  spawns daemons must not segfault or corrupt.
- **One static binary per target** with mature cross-compilation - the
  installer script stays a trivial download.
- **Ecosystem fit:** clap, serde, and the tooling (rustfmt,
  clippy, cargo test) give the project its quality bar for free.
- **Contributor gravity.** Rust's strictness scales to big contributor
  counts: the compiler enforces what style guides plead for.

## Consequences

- Build times are longer than Go; mitigated by a small dependency tree
  (each dependency is argued in the workspace manifest) and CI caching.
- Some contributors don't know Rust; mitigated by layered architecture
  (CLI handlers are beginner-friendly), docs, and good-first-issue labels.
- Async (tokio) is deferred to M2's service manager and scoped there;
  M1–M3 logic is synchronous and stays simple.
